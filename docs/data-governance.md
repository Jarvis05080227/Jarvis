# 治理数据 (README 第 2 节展开)

> 示例里的人和事都已抽象成「一封邮件」「一条承诺」。数字带出处; 出处里的路径指私有仓, 公开仓里能看到的模块标了 `core/`。

## 总纲: 治数据, 不治检索

2026-08-27 定下的设计地基令, 要义是: 后面的设计以治理记忆、规范记录为主, 不在怎么调用、怎么精准获取上大费周章。模型一代比一代强, 只要把形态合理的记忆注入, 下一代模型自己就找得到要的东西; 这是模型迭代白送的。数据是十年、二十年的资产。

这条令有数据撑着。30 个长期记忆出错的案例按「存、进、取、用」四环逐个归因: 53% 病在账本身 (存错了), 30% 病在写进去的管道, 检索侧只占 13% (私有仓 `docs/process/JARVIS_MEMORY_GOVERNANCE_CHARTER.md`)。

落到取舍上是三句话:

1. 方案二选一时, 治数据 (分类、单一账本、销账级联、事实时间、规范 schema) 优先于治检索 (排序、相似度、花哨管线)。
2. 新存储按「十年后换了三代模型还能直接读」设计: 人可读, 自描述, 带 id, 不和当前管线耦合。
3. 噪声在源头修, 不在过滤器上修。

体索引是最近的一个例子 (见 `architecture.md` 第 3 节): 用户问起一件事, 检索撞上了碎片, 查下去材料全在, 缺的是边。修的是边和账, 「有主」从 29.6% 升到 99.11%。

## 证据面禁硬切

**案例。** 一个审计腿要判断「这句话有没有依据」, 它把最近四轮对话拼成一条, 再截前 600 字。用户刚说完的那句恰好落在截口外面。于是审计腿把用户自己的原话判成了幻觉, 贾维斯接着自责了三轮。同形的案子当时攒了三起。

**为什么会反复出。** 头截 `x[:N]` 保留的是最旧的内容, 而证据几乎总是旧在前、新在后。被切掉的, 恰好是当下这件事的直接依据。此前只有一条笔记和一个只管读口的软标, 射程够不着证据面, 所以一犯再犯。

**立的法。** 2026-08-30 写进接地法典最高一节: 一切进 prompt 的证据面禁硬切。合法的路只有两条:

- `cap(site, text)`: 全文透传, 超过软标只报警, 原样放行。
- `units(site, items, render, budget, keep_newest)`: 要丢就丢整单元, 最新的恒收。

唯一的豁免形要三条同时满足 (在行界切、显式标出切了、帽可配置) 并在同一行写理由。执行器是一个提交前检查: 基线是当时存量的 483 处、96 个文件, 只许降不许升; 2026-09-02 降到 0 (私有仓 `scripts/hooks/evidence_cut_baseline.json`)。工具回执整段进 prompt 也算证据面。

实现: `core/jarvis_evidence_face.py`, `core/jarvis_honest_clip.py`。

## 保证只认机器闸

**案例。** 一个施工窗只接了一半的料, 就报「两条出境路的口径已一致」; 第二天补料时又漏了两样。两天两次「加了这个漏了那个」。问题不在贾维斯, 在施工: 每个窗口只验收自己摸过的那块, 却把保证说成系统级; 保证比会话活得久, 下一个窗口戳破它时, 在用户眼里就是又一个新错。

**立的法。**

1. 「不会再出」「已一致」「保证」必须指着机器物说: 一个测试名、一个闸名或一个棘轮。指不出来, 只许说「降低了概率」, 并说明验收面的边界。
2. 口径类的保证只有一种合法形: **登记册 + 锁测**。出境信的料登记在一张单子里, 两条路都遍历这张单子, 锁测逐项断言; 以后加新料就是往单子里登记一行, 在第二处手拼即违规。
3. 收录判据要明说, 豁免也要明说: 豁免是声明过的决定, 不是漏。

这一节后来写成了一篇公开文章, 见 `articles/T9_保证只认机器闸_知乎版.md`。

## 记错比忘了更糟

**原则。** 2026-09-24 定: 新说法如何覆盖旧说法, 是记忆落账最关键的一步; 错的信息录入, 比什么都不记得更严重。忘了还能问, 记错了连问都不会问, 而且会被当成现行事实反复用、反复说出口。

**做法。** 凡是落账、去重、合并、覆盖的设计 (联系人卡上的事实、别名并卡、画像), 拿不准「是不是同一件事」时走保守形: 新旧并存, 标冲突, 送裁; 不静默覆盖, 不静默合并。反过来, 把用户新说的丢掉也算错。

**怎么验收。** 量两个数: 改口被认出的比例, 和复述被误当成改口的比例。只量一个数, 两头总有一头会塌。

画像的改动走一个带审计、全文历史、可撤回的写口, 不直接写文件。

## 阈值按真数据定

**案例。** 同一个窗口里两把余弦相似度尺子, 都先按手感定, 都被真数据推翻, 方向还相反:

| 尺子 | 手感 | 真数据 | 改为 |
|---|---|---|---|
| 承诺对账: 一封信里说的事, 是不是卡上已记的那条承诺 | 0.55 | 同一件事中英跨语种只有 0.50, 不相干的 0.31 | 0.45 |
| 卡片去重: 两条记录是不是副本 | 0.85 | 只量一个族时缺口看着很宽; 把另一个族也量进来, 真副本低到 0.795, 真正的缺口是 0.679 到 0.795 | 0.75 |

0.55 会把一条真落下的账冤判成假账; 0.85 会漏掉一半真副本。

**立的法。** 落任何相似度阈值之前, 先拿真数据全量跑一遍两两相似度, 打印最像的 N 对和中段的 N 对, 找出「真是同一件事」和「不是」两团之间的缺口; 阈值取缺口中间偏正例那一侧 (漏判可以下一封信再审, 冤判会当场支使人去补一条本来就在的账, 代价不对称); 量到的两个数字写进代码注释。只量一个族就定阈, 是样本不全。

## 账本的几条硬规

- 全仓持久化的 append 只有一个合法口, 每行带信封 (`core/jarvis_ledger.py`)。
- 主账本原子写: tmp 文件 + fsync + `os.replace()`, 禁止裸 `open(path, 'w')` (`core/jarvis_store_contract.py`)。
- 任何拦截都必须落一行判决账, 拦了不记等于违法 (`core/jarvis_decision_gate.py`)。
- 所有改动有总账旁录: 谁, 什么时候, 改了哪本账的哪一条 (`core/jarvis_hand_audit.py`)。
- 推断产物带认识论标签, 标明是观察、推断还是猜测 (`core/jarvis_epistemic_label.py`); 记忆条目带「该多信」的元数据和「帮了还是害了」的 credit 账 (`core/jarvis_metamemory.py`, `core/jarvis_memory_credit.py`)。
- 读侧校验 schema 版本, 不符先记账, 闸开才拒读 (`core/jarvis_schema_readside.py`)。
