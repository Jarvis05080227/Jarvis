# 视频补充说明 ·《AI 的长期记忆为什么会记错？个人 Agent 记忆架构分享》

> 视频三分钟，只能讲个大概。这篇把视频里一句带过的地方展开：具体怎么做、数字怎么量的、哪些还没做到。
> 更完整的工程细节见 [`memory.md`](memory.md)。
> 片中「小雨」是化名，香菜是举例；数字都是贾维斯私有仓 2026 年 10 月的实测，私有数据不公开，所以这些数字没法在本仓复现。

## 1. prompt 是什么，为什么会写不下

大模型本身不记事。每次回话前，程序会把一份材料拼好交给它，这份材料叫 prompt。它「记得」什么，全看这份材料里写了什么。

材料有长度上限，而且越长越慢、越贵。贾维斯近 7 天的实测：主脑和人对话时，一份 prompt 的中位数约 19 万 token；后台思考的那颗脑约 26 万 token。

聊得越久，要放进去的东西越多，迟早写不下。这是所有长期记忆方案都要面对的事。

## 3. 「原话全留着，摘要只当目录」具体是什么意思

- **原文永不删。** 原始语料按字节存一份指纹（sha256），有一条测试专门守着「永不删除」。
- **摘要还在做，但不再顶替原文。** 一条摘要被检索命中时，送进 prompt 的是它指向的那几条原文，摘要本身只当索引页。
- **我们也压过。** 早期把一周前的闲聊压成摘要，再把原文软删掉。后来普查：107 条摘要里，只有 13 条还能追回原文；一段时间里共同经历在检索里整片消失。这一段是改成「原文才是内容」的直接原因。
- **给每条记录写标题时，模型读的是全文**，不是截前几十个字（有测试检查不许切片）。

## 4. 「五万条记录、十万多条线」是什么

贾维斯把所有记录统一编进一张图，节点分四种：

| 名字 | 是什么 | 例子 |
|---|---|---|
| 点 | 一条原始记录 | 一句话、一封信、一次工具调用的回执 |
| 线 | 有开有关的事 | 答应过的事、还没解决的关切；办完才关 |
| 面 | 一件事的名字，把相关的点归在一起 | 「找工作」 |
| 体 | 一个人或主体 | 某位朋友；贾维斯自己也是一个体 |

2026-10-25 重建统计：点 50,072 / 线 9,749（开着的 966）/ 面 80 / 体 25；边合计 105,722 条。

边从哪来：绝大多数是**机器按规则连的事实**（这句话是谁说的、这条记录属于哪封信、这件事推进了哪条线），不靠模型猜；两颗脑在对话中确认、亲手连上的只有 846 条。挂靠关系记在一本只追加的账里，改挂靠是新增一行，旧行不删。

## 5. 「问到一个人，顺着线往外多走一层」

- **起点**：这一轮被点到名的人，加上最近几轮对话里在场的人（谁说过、谁被提到过）。用名字表确定性匹配，不去猜代词。
- **第一层**：这个人名下直接挂着的面、线、点。
- **第二层**：顺着边往外一步。连着的人、连着的事、推进过的线。实际走几步看边的类型，约一到两步。
- **再往外不取。** 这一次不需要。
- **关键词 / 语义检索没有去掉。** 它们照样在跑，负责网上连不到的东西；关系网负责「名字不出现、但确实相关」的那部分（片中「弟弟要手术」那条）。

**还没做到的**：设计里，每条线有「亮度」（没了结的常亮、刚提到的变亮、久不用的变暗），用来决定先想起哪些，并在亮度升高时主动叫醒后台那颗脑。这部分代码已经写了，开关还没开，所以视频里没讲。

## 6. 「0/60 → 60/60」是怎么量的

2026-10-22 做的离线回放，不是线上实测：
- 取一位朋友的 30 轮真实对话，盯两条关于她弟弟的记录。
- 老的做法（按「最近 7 天、点名近况」取）：60 次机会里一次都没进 prompt。
- 新的做法（关系网 + 分档放置）：59 次以一行标题出现，1 次出现在「当天新记录」那一区，60 次全在。

## 7. 「46 万字 vs 25 万字」和「不剪」

- 同一位朋友，把所有相关记录不加选择全摆出来，中位约 46.5 万字；而当时整份主脑 prompt 的中位约 25 万字。全放是放不下的。
- 放不下时分四档：**原文 / 一行标题 / 一组只留编号 / 这次不放**。每一档都完整，不会出现半句话；页脚会核对总数，确保没有记录被漏掉。
- 一组记录可以用工具当场展开成原文。
- 分档后，设计时量的那位朋友中位约 9.3 万字。这是设计阶段的测量，不是线上实测。

## 8. 「谁写了截断，提交就被拦下」

往 prompt 里放内容，只允许三种写法（代码见 [`core/jarvis_evidence_face.py`](../core/jarvis_evidence_face.py)）：
- `cap()`：全文照放，超长只报警，不切。
- `units()`：放不下就整条丢，最新的一定留。
- `tiers()`：降一档放（原文 → 一行标题），但不切半句。

提交代码时有一道检查，发现新写的截断（比如 `text[:80]`）直接拒绝提交。立这条规矩时全仓有 483 处这样的截断，后来清到了 0。

## 9. 「按变不变排队」和 86%

- 主脑的 prompt 由一张 93 格的登记表决定顺序，分三段：几乎不变的身份区（它是谁、对面是谁、能做什么）→ 偶尔变的状态段 → 每轮都变的部分（刚找出来的记录、刚说的那句话）。
- 排序按「变不变」，不按「重不重要」。前面不变，模型服务端就能复用上一次的计算（prompt 缓存），回得更快，也更便宜。
- 实测近 7 天：后台思考那颗脑 86.2% 的输入命中缓存；**主脑对话只有 61.3%**，视频里没提这个数。我们的目标是 90%，两边都还没到。
