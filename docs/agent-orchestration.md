# 调遣 agent 军团施工 (README 第 3 节展开)

> 贾维斯私有仓到 2026-10-10 有 7,262 笔提交、553 个模块, 代码几乎全是 AI agent 写的。我的工作是管它们。下面每条规矩都标了执行器; 没有执行器的如实写「靠自觉」。模型按档位称呼: 统筹档最贵、额度单独计; 施工档次之; 侦察档最便宜。

## 1. 统筹只做四样

统筹窗的岗位只有四样: **需求澄清、方案拆解、任务分发、结果验收**, 外加贯穿四样的判词和对我的呈报。实现类工作 —— 读大量代码、写代码、跑测试、批量修改 —— 默认全部派出去, 不按活的大小挑拣, 不派的那一次要给理由。统筹在这四类活上的正当动作只有三个: 写 spec, 读回报, 盖章或驳回。

亲手做的例外只有三条: 不可逆的外向动作 (提交、改主账本、翻闸 —— 派出去的是 diff, 落地的手是统筹)、一行级的微活、判词载体本身 (交接话术、呈报文书、长期记忆)。

**为什么。** 这条规矩改过三次。最初按「总 token 最省」派活, 结论是判断类的活让施工档建、统筹档验, 等于付两次钱, 不如统筹亲手干。2026-09-03 看了真实账单: 额度是分池的, 统筹档的专项周额度用到 91%, 全模型池才 59%, 5 小时窗口 4%。撞墙的只有一堵。于是换了成本函数: **要省的不是总 token, 是统筹池的每一口**; 只要能把活挪到别的池子, 总 token 翻倍也赚。同一天又把岗位收窄成上面四样。

判例一句话: 成本判据必须写明按哪本账算; 换了账本, 老结论不自动继承。

## 2. 派单

- **spec 首行写 `model=`。** 不点名, 子代理就继承统筹的模型, 施工按最贵的价计。执行器: 派单前的钩子, 缺省、继承、点错档位 (施工只放施工档, 侦察只放侦察档) 一律拦下, 并把章程原句回灌给统筹。兜底: 环境变量把缺省子代理模型设成施工档。
- **禁 fork。** fork 继承统筹的全部上下文, 整卷按统筹价重算。执行器: 同一个钩子。
- **spec 必写三样**: 产物落在哪个目录、数字要带出处 (文件:行 或 命令)、判词标为假设。
- **测试范围写死。** 2026-09-27 一次 14 分钟的改码, 因为 spec 只写了「跑相关集」, 施工兵自选 148 套跑了 65 分钟, 红了 87 个再逐个回旧版本判是不是旧病。根因在统筹。之后 spec 必列套件或写上限; 没写时默认: 逻辑改动 ≤10 套, 改运行时行为 ≤20 套; 候选超上限施工兵不自己放大, >30 套先报批; 单条测试命令跑过 15 分钟就停下。执行器: 靠自觉, 施工兵提示词里有一条。
- **能拆的小修单独派**, 与大单并行; 设计在等拍板时, 不依赖那个判断的部分先派出去。缘起: 一个窗口近四小时只落了一项, 两个一行级的小修被塞进大单一起等。

## 3. 回报与验收

- **回报 ≤40 行结论卡, 全文落盘。** 全文回灌主窗等于同一份内容付两次钱, 还永久垫高之后每一轮。2026-08-27 的账单: 77% 的用量发生在超过 15 万 token 的长窗里, 63% 来自重子代理会话。实证反例是一次六路侦察全文回灌, 主窗被垫了几十万 token。
- **三级信任**: 数字抽验载重的前三个, 错一个就升级全量复核; 事实引用时标来源; 判词一律重下, 只当假设。会变的数字 (活体状态) 落刀前重打一次探针 —— 有一个状态文件从「不存在」到「有首例」只隔了 3 小时。
- **快不换松。** 子代理的做法可以放手, 验收不减: 回报逐条对齐需求方的原话, 依据分三层 (原话 > 已准的推荐 > 统筹自拟), 对不上的退回返工, 子代理自己拿的主意单列呈报。
- **报「已生效」的口径。** 改了代码一律报「绑重启」; 只有被已加载代码实际读到的覆盖层键可以报「热生效」。
- **回执七项。** 任何施工线收工都写回执: 模型型号串、diff 统计原行、测试原行、文件清单、提交号或「未提交」、闸态、待办。缺项, 验收人有权不看。验收人是不施工的那一个。

## 4. 子代理的寿命

续用同一个子代理, 每条消息都把它的整卷历史重放一遍。2026-08-27 有一个施工兵从 27.6 万 token 拖到 66.6 万, 越续越贵。规矩: 过约 30 万或连续三单就退役, 落交接文档 (落点行号、闸态、未竟事), 新兵读档冷启。冷启的成本小于拖卷的成本。追加指令攒成一批发, 一条大消息胜过五条小消息。

统筹自己也一样: 一案一窗, 关账就清窗; 不在已经超过 15 万 token 的窗里追加新案。

## 5. 什么时候必须上报

施工档很可靠, 所以大部分统筹也交给它。但有一条告知义务: 命中下面任一条, 就要告诉需求方「这件得上统筹档」:

| 条 | 触发 |
|---|---|
| T1 | 没有验收口: 对不对写不成测试或脚本, 只能靠判断 |
| T2 | 需求有两种以上读法, 而且做出来差别大 (这条去问需求方) |
| T3 | 要在两条规矩或红线之间取舍, 或要立新规矩 |
| T4 | 牵动广且难撤: 改主账本 schema、跨 3 个以上模块接线、改到达主脑内容的结构 |
| T5 | 同一件活验收被驳两次 (量出来的, 不是感觉) |
| T6 | 自评没底, 而且说得出卡在哪一个判断、为什么 |

为什么不只靠「觉得可能错就报」: 判断一件活**是什么形状** (有没有验收口、有几种读法) 是看得见的任务特征, 能信; 判断**自己这次会不会错**不能信, 最贵的错是自己没察觉的错。立档当天就有两例: 一个统筹窗把需求读窄了, 当时没觉得有歧义; 一个侦察兵标了「假设」却没觉得不稳, 被抽查推翻。

所以报了什么、漏了什么都记账。「漏」= 事后被追问、抽查或验收驳回发现的错, 当时没报。到 2026-10-10, 账上「报」28 行, 「漏」35 行。漏比报多。这个数就是「自评能信几成」的回答, 它比任何保证都诚实。

## 6. 钩子当执行器

「无执行器不算法」。章程里每一条都要钉到执行它的文件上, 没有的如实标「靠自觉」。执行器分三档: **拦** (违规做不成) > **默认值** (设错也不落到贵的池子) > **提示 / 在场** (每轮出现在眼前, 仍可无视)。

| 规矩 | 执行器 | 档 |
|---|---|---|
| 派单显式 `model=`、禁 fork、档位按族 | 派单前钩子 | 拦 |
| 同上兜底 | 缺省子代理模型的环境变量 | 默认值 |
| 额度分档、上下文过 15 万提醒 | 每轮报池子读数的钩子 | 提示 |
| 折叠上下文前留底 | 折叠前自动备份的钩子 | 在场 |
| 证据面禁硬切 | 提交前检查第七腿, 基线只降不升 | 拦 |
| 主账本原子写 | 提交前检查第十腿 | 拦 |
| 章程体积帽、条款必带日期标签 | 提交前检查第八腿 | 拦 |
| 回报 ≤40 行、子代理限龄、上报义务 | 子代理提示词 | 提示 |

明确不做的也记下来, 防止日后重开: 强制清窗 (任务中途被折会伤质量)、自动压缩窗口、降推理档位。

## 7. 三方独立设计

难的设计不让一个人拍。体索引那次的做法 (详见 `architecture.md` 第 3 节): 题面只给问题与约束, 不给任何一方的调研结论; 三条线各自调研、各自出稿、互不看稿; 设计期只读。汇总时把分歧摆成表, 逐条标「已核」和「各稿自报」, 抓到一份稿的病因判错。之后由统筹档出施工 spec, 施工档单线施工, 验收带对照臂。

**「验收过」要有对照臂**: 每个结果都要能和现状对照, 标准是比现在更强, 不是「不像现在」。新加的锁测要先在旧代码上跑红、改后跑绿, 证明它咬得住。

## 8. 返工账: 做视频的手册

`media/` 里那部片子是同一套方法做的: 统筹写台词与分镜, 施工兵写渲染代码。它的手册开头写着: 前后两天多, 返工的根子几乎都在「内容没定就开画面」和「每段没讲清问的是什么」。

| 返工 | 根子 | 下次 |
|---|---|---|
| v9 整片作废 | 画面一格一个场景, 没衔接; 一单塞 35 格, 降级成剪贴画 | 先做一段样片定风格 |
| v10 两段作废 | 内容没定, 讲太多, 没总结 | 先定台词表, 再开画面 |
| v11 第一级重做两次 | 问题和证据对不上, 问题没亮出来 | 问 → 证 → 答, 问题要证据答得上 |
| v12 后段重做 | 开场缺引子; 概念没交代; 卡太密、换场太勤; 结论落在静音里 | 写进手册三条: 引子、卡的密度、音乐撑到片名 |

手册第一条因此是: **台词表先定死, 再开画面**。

## 9. 一句话

下判断的只有一处, 动手的可以有很多, 每只手都交回执, 回执对不上就叫醒下判断的那一个。这和贾维斯内部主脑、思考脑、回执的关系是同一个形状 (见 README 第 1.5 节)。
