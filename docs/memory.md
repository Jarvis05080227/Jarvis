# 贾维斯的长期记忆: 体、识、说与数据治理

> **English summary.** This note explains how Jarvis keeps long-term memory without compressing the original records. The core is prompt assembly: a registry of 93 blocks in three cache zones, ordered by volatility rather than importance, with keyed blocks that cost zero bytes when nothing matches.
> Memory reaches the prompt through a graph: the **Body** indexes every record with a traceable source handle and graded edges; the **lens** projects what the current turn needs at four resolutions (full text / one line / group / not included), never dropping a unit silently.
> A brightness layer (salience, one-hop spread, waking the thinking brain) is written but switched off; we say so where it matters.
> We also compressed chat into summaries once, and lost track of the originals. The fix was a rule: summaries are a table of contents, the original is the content. Numbers are from the private tree on 2026-10-25. Docs are in Chinese.

> 示例里的人和事都已抽象成「一位朋友」「一封信」。数字带出处, 出处里的路径指私有仓; 判断写成「我们的判断」, 不写成结论。

---

## 0. 为什么写这篇

这个月, 社区在给 DeepSeek 的「大肥鱼」装记忆, 讨论区里吵得很热。吵的几个病, 我们都认得:

- **压缩有损。**「DSH 自带 summarize，但压缩有损，细节会丢」([deepseek-harness 讨论 #1052](https://github.com/deepseek-ai/deepseek-harness/discussions/1052))。
- **改错条目。** 一个记忆插件的回执只显示 8 位截断 id, 碰撞时「看起来成功；实际被改的是同前缀下…最先命中的那条」([dsh-meow-memory #62](https://github.com/Phant0Meow/dsh-meow-memory/issues/62))。
- **各记各的。** 多个 agent 跑起来, 记忆「变成"每台各记各的、互相不知道"」([dsh-multi-agent-cluster README](https://github.com/dsh-xiaoyi/dsh-multi-agent-cluster))。
- **压缩与缓存两难。**「如果不记住所有的上下文，就完全无法命中缓存…消耗的钱更多。还不如快封顶之后做summary压缩」(同 [#1052](https://github.com/deepseek-ai/deepseek-harness/discussions/1052))。

这些是所有记忆系统都会撞的墙, 我们也撞过, 有几面撞了不止一次。下面讲我们现在的做法、它在哪里还没做到, 以及我们自己压缩过、后来退回来的那段旧账。

## 1. 一句话答案

**原文不压缩。体负责找全, 识负责排轻重, 说负责放进 prompt。**

「体」是一切记录的索引, 带着能追回原账的出处句柄; 「识」是索引上的边和亮度, 决定哪条更要紧; 「说」是透镜和 prompt 装配, 决定这一轮主脑看到什么、以多大的分辨率看到。三样里, 边和透镜已经在线上跑; 亮度的代码写好了, 闸还没开。

开头那四面墙, 我们现在站在哪, 先列在这里, 局限一起列:

| 墙 | 我们的做法 | 还没做到的 |
|---|---|---|
| 压缩有损 | 原账不删, 摘要和标题只当目录, 全文能用工具回读 (第 7 节) | 思考脑长窗口的折叠摘要本身有损 |
| 改错条目 | 身份账、志账只追加, 修订和撤回都是新事件, 旧行留史 (第 3、6 节) | 更正传播只写票, 下游不自动改 |
| 各记各的 | 87 本源账进同一个体索引, 两颗脑读同一行索引 (第 2、3 节) | 绝大多数边是机械连的, 脑确认的只有 846 条 |
| 压缩与缓存两难 | 按易变度分三段缓存, 折叠至多一小时一次 (第 2、5 节) | 近 7 天主脑对话命中 61.3%, 没到 90% |

记忆系统的胜负, 最后落在 prompt 上: 东西存得再全, 进不了 prompt 就等于没有; 进 prompt 的方式不对, 缓存就破, 钱就烧。所以这篇从装配讲起。

## 2. prompt 怎么装配

### 2.1 一张登记表, 三段缓存

主脑的 prompt 不是一个大字符串拼出来的。它由一张块登记表驱动, 表上 93 格, 每格是一块内容, 写明它是什么、归哪一段、什么时候发 (私有仓 `memory_pool/prompt_layout_registry.json`)。

| 段 | 放什么 | 缓存行为 |
|---|---|---|
| system | 身份区: 诚信墙、人格核、画像卡、共同史、工具菜单 | 字节稳定, 进前缀缓存 |
| u1 | 状态半静段: 交办、关切、立场、准则、未了之事 | 变了才重渲 |
| u2 | 动区与本轮: 传感、刚发生的事、召回、本轮输入 | 永不进前缀缓存 |

登记表头上写着几条铁则, 我们觉得这几条比任何检索技巧都值钱:

1. **排序按易变度, 不按重要度。** 越稳的越靠前, 越易变的越沉底。重要的东西放在底部不会被模型忽略, 易变的东西放在顶部却会让后面的缓存全部作废。
2. **段管缓存, 选择管发不发。** 一块内容在哪一段, 和它这一轮发不发, 是两个独立的决定。
3. **keyed 块零命中就是零字节。** keyed 块是「本轮点名命中才发」的块, 比如某件关切的全文、某个人的近况; 没点到, 它不占一个字节, 也不留空标题。

新的大块要进来, 只有两条路: 进前缀并且只追加, 或者沉到尾部。破缓存的机制直接退, 这是我们的家法, 不是建议。

### 2.2 从上到下, 主脑看到什么

按登记表的认知序摘要, 分七层:

| 层 | 内容 | 段 |
|---|---|---|
| 1 身份区 | 诚信墙、人格核、自身外观、画像卡、身份面向、共同编年史与摘要、能力边界 (工具菜单)、角色 | system |
| 2 状态半静 | 用户交办、关切摘要、关系锚、立场、「我持有的」规则、行为准则、人生里程碑、昨日与今日小结、时间感、**体: 未了之事全局表**、生活线 | u1 |
| 3 传感与欠账 | 在场情况、受话证据、屏幕账、当前项目、欠账窗、用户纠正、近期完成、我的错误史、承诺对账、开放提问 | u2 |
| 4 世界与上轮 | 世界实况、刚发生的事 (短期记忆 + 工具回执)、思考线摘录、时钟、生活日志、后台腿、重启台账、刚提到的联系人 | u2 |
| 5 keyed 命中簇 | 关切全文、**体: 透镜尾段**、立场、关系碎片、证据片段等; 无命中零字节 | u2 |
| 6 召回与教学 | 长期记忆检索块、去年今日、决策判例、工具经验、常驻教学、已核事实权威卡 | u2 |
| 7 本轮 | 用户原话、话头、记忆标题索引 | u2 |

对内说话只走一个装配函数, 对外写信只走另一个 (私有仓 `jarvis_prompt_assembly.py` 的 `_assemble_prompt` 与 `_assemble_outbound_prompt`)。出话面只有两张口, 这是设计准则第 12 条。

还有一处不在表上: 透镜的索引块不进登记表, 而是作为思考脑心流账里的一行窗行, 两颗脑读同一行 (私有仓 `jarvis_body_lens_supply.py` 头注)。它首拍追加进历史, 之后不再重写, 所以既不破前缀, 也不会出现「思考脑看得到、主脑看不到」。

### 2.3 网状注入: 从一个名字到一张面

主脑这一轮该知道什么, 我们不靠向量相似度去猜, 而是顺着边走。

起点叫种子, 有两个来源: 本轮被点名的人或事, 以及「在场集」—— 活窗口里用户说过的、贾维斯自己说过的、思考脑念头里提到的名字; 折叠水线越过去, 就离场 (私有仓 `jarvis_body_lens_presence.py` 头注)。名字用名表确定性匹配, 不猜代词。

从种子出发, 沿体索引里的边取「相关集」, 按边的类型分层, 不按裸跳数 (私有仓 `jarvis_body_view.py`):

| 层 | 取什么 |
|---|---|
| A | 种子直连的角色边对端的线和点, 以及种子所在的面 |
| B | 种子面的成员: 主父子树, 加上以「也在」挂进来的记录 |
| C | 推进了 A、B 里某条线的记录 —— 没点她的名、只推进她那件事的记录, 从这一层进来 |
| M | 正文里字面写了这个名字的记录 |

算下来是一到两跳, 由边的类型决定, 不是任意 N 跳的扩散。取出来的记录按「同一原件」折成单元, 再按一张「没意义才不进」的规则表分桶, 每条规则自带理由; 页脚守恒, 相关集加各桶等于全集。

这就是「网状注入」: 进 prompt 的不是「和这句话最像的 k 条」, 而是「和这个人、这件事连着的全部」, 再交给透镜决定每一条以什么分辨率排开。线上的「网」到此为止, 是带类型的边加种子; 激活扩散那一层还没开, 见第 4 节。

### 2.4 放不下怎么办: 透镜四档

「全部」很快就放不下。我们量过一次: 朴素地把一位朋友的全部相关记录都放进来, 透镜面中位 46.5 万字, 是整份主脑 prompt 中位 (25 万字) 的 1.9 倍 (私有仓 `BODYALL-1021` 开窗话术 §13)。

透镜的答法是降分辨率, 不丢单元。每个单元落在四档之一:

| 档 | 形状 |
|---|---|
| 全文 | 原文整段 |
| 一行 | 该记录自己的完整字段 (标题、时间、出处), 不是截断的正文 |
| 组 | 一组同类记录压成一行计数, 零正文, 例如「2026-09 念头 ×212 → 组号」 |
| 不进 | 不进 prompt, 但计入总数 |

页脚有一条守恒式: 行数 + 组内条数 + 今日新生 + 不进 = 全集单元数。主脑需要哪一组, 用工具 `body_lens expand <组号>` 展开 (私有仓 `jarvis_body_lens_groups.py` 头注)。分组加行预算之后, 同一位朋友的透镜面降到中位 9.3 万字; 这是设计探针上的数, 不是线上实测。

所以对「放不下」的回答不是「压成摘要」, 而是「看得见自己没看到什么, 并且一步就能展开」。

### 2.5 证据面: 三条合法路

一切写进 prompt 的证据, 只有三条合法的路 (私有仓 `jarvis_evidence_face.py`):

- `cap()`: 全文透传, 超过软标只报警, 原样放行。
- `units()`: 要丢就丢整单元, 最新的恒收。
- `tiers()`: 降档不丢单元; 一行档只许是该单元自己的完整字段。

头截 `x[:N]` 保留的是最旧的内容, 而证据几乎总是旧在前、新在后, 切掉的恰好是当下这件事的依据。透镜四档就是 `tiers()` 的一个用法。执行器是提交前检查的第七腿 `evidence_cut_lint.py` 和锁测 `tests/_test_evidcut_law_1.py`: 存量截断从 483 处清到 0, 零容忍的四本基线合计为 0, 另一本宽档基线 281 只降不升。工具回执整段进 prompt, 也算证据面。

### 2.6 体量与缓存, 照实写

近 7 天、prompt 超过 5 万 token 的调用, 从私有仓用量账 (`memory_pool/main_brain_usage.jsonl`) 量出来是这样 (单位是 token, 不是字):

| 调用 | 次数 | prompt 中位 | 缓存命中 (按 token 加权) |
|---|---|---|---|
| 主脑对话 | 276 | 189,435 | 61.3% |
| 思考脑 | 1,550 | 262,434 | 86.2% |
| 工具续轮 | 41 | — | 75.3% |
| 写信草稿 | 37 | — | 42.6% |

我们给自己定的目标是 90%, 四路都没到。思考脑最接近; 主脑对话这一路差得最远。主脑对话这一路为什么低, 我们还在查。

## 3. 体: 网下面的骨

### 3.1 四类节点

体是对所有源账的派生索引, 原账不搬 (私有仓 `jarvis_body_index.py` 的 `rebuild_index`)。源登记表上登记了 87 本源账 (10-10 公开版写的是 107 本, 两次的计法不同)。源适配器只读, 把每本账枚举成统一形, 并自检一条不漏等式: 原始条数 = 收录 + 折叠 + 跳过。

| 节点 | 含义 | 2026-10-25 |
|---|---|---|
| 体 | 人或主体: 用户、AI 自己、联系人卡上的人 | 25 |
| 面 | 一组事的共同名字 | 80 |
| 线 | 有开有关的条目: 承诺、关切、议程 | 9,749 (开着 966) |
| 点 | 单条记录: 一封信、一个念头、一条回执 | 50,072 |

合计 59,926 个节点, 记录种类 95 种 (命令: 私有仓 `scripts/body_dump.py rebuild` 只读重建, 不写活池)。

### 3.2 出处句柄

每个节点都带一个能追回原账的句柄, 形如 `turn:<id>`、`mail:…`、`concern:…`、`promise:…`, 子记录用 `#` 接在后面, `#vN` 表示版本。体只持指针; 要原文, 顺着句柄回原账去读。

### 3.3 身份账: 只追加

谁、在哪一轮、把哪条记录挂到哪张面, 每一次都落一行身份账。身份账只追加, 永不衰减、永不修剪, 任何形状的调用都落行而不拒绝 (锁测 `tests/_test_blockflow_d1_body.py::test_never_decay_never_prune` 与 `test_link_never_refuses_all_shapes`)。要改挂, 就新增一行解挂, 旧行不动。

到 10-25, 身份账 13,483 行: 挂接 12,474、解挂 834、看过 118、新开面 57。

### 3.4 边: 机器连事实, 判断留给脑

边按等级分六档 (10-25):

| 等级 | 条数 |
|---|---|
| 实 | 38,705 |
| 默认 | 35,561 |
| 机械 | 15,947 |
| 派生 | 14,620 |
| 脑 | 846 |
| 候选 | 43 |

六档相加 105,722 条。绝大多数边是机械规则连的事实, 零模型调用: 外键、发件人与收件人、同一原件、机器流水默认归 AI 自己。两颗脑当轮确认的「脑」边只有 846 条。我们的判断是, 这个比例是对的: 能写成规则的事实交给规则, 「这件事归哪张面」这种判断才交给脑, 而且相似度不单独成边。

## 4. 识: 边已在用, 亮度还没通电

「识」是我们对索引上权重层的叫法。它分两半, 现状不一样, 分开说。

**边, 已经在用。** 上一节的带等级的边, 加上点名和在场的种子, 就是线上透镜今天走的路。

**亮度, 代码已写, 闸未开。** 设计是这样的: 事实不学, 只增不改带出处; 亮度会学。四档亮度 (私有仓 `jarvis_body_bright.py` 头注):

| 档 | 条件 |
|---|---|
| 3 常亮 | 开着的线且近期有进展 / 本轮点名 / 当日新生 |
| 2 | 7 天内有进展, 或 30 天内有脑确认的边 |
| 1 | 90 天内 |
| 0 暗 | 其余; 变暗不删 |

没了结的线常亮; 被反复提起、被纠正过的加粗; 扩散只走一跳, 只从线到记录, 封顶 3 条。亮度只管升档、排序和醒因, 不当门 —— 暗了的东西照样找得到, 只是排在后面。7、30、90 天这三条线是临时值, 要等真数据来定。

这一层的闸现在是关的, 关闸时 `bright()` 恒返空, 透镜按「进展新到旧」取舍。

**亮度唤醒思考脑, 在施工。** 设计已经拍了三条: 只认升到 3 档才醒, 只认新事实才再醒, 不做影子账。施工排在量尺之后, 还没上线。

旧的一套关系网 (6 月写的, 余弦织边加周期衰减) 还在跑, 但它的点是旧命名空间, 和今天的体账不通。我们的决定是换底: 算法搬到体句柄上, 旧网冻结归档, 不删。

## 5. 短期与长期记忆的检索口: 现在还剩哪些

体和透镜负责「找全」, 但它们不是唯一的路。主脑这一轮看到的记忆, 还从另外几条口进来; 有的在线, 有的关了, 有的被接走了。

### 5.1 短期记忆是三层, 不是一个桶

| 层 | 是什么 | 进 prompt 的方式 | 现状 |
|---|---|---|---|
| 近轮 | 刚发生的几轮, 内存里一份, 落盘一份供重启恢复 | 取最后 6 条, 上限 2,000 字; 写信口 16 条、12,000 字; 每条带说话人标签 | 在线 |
| 心流账 | 思考脑的长窗口, 只追加 | 窗口 60,000 token, 用到 85% 时把出窗的旧轮折成「早前摘要」, 折到 40%; 至多一小时折一次 | 在线 |
| 真消息数组 | 把近轮还原成逐字的多轮消息 | 取最后 24 轮 | 写好未开 |

(私有仓 `jarvis_mind_stream.py`、`jarvis_mind_stream_fold.py` 头注; 配置为覆盖层生效值。)

心流账折叠时原行不删, 折叠失败就机械裁剪兜底。一小时一次的下限是为缓存定的: 折叠一次, 前缀就变一次, 折得越勤缓存越碎。翻章有三道界: 真睡、会话结束、日界; 新章第一条是上一章的摘要、未了之事的快照和自传的章尾。

这里有两处要照实写。一是折叠摘要本身有损, 补偿靠体索引和原账能回溯, 不靠摘要; 二是近轮那一层超限时在头部加省略号截尾, 是前面说的「只剩 3 处」字面截断之一。

### 5.2 长期记忆的检索口

| 检索口 | 机制 | 现状 |
|---|---|---|
| 语义腿 | 向量余弦, 最低相似度 0.3; 按年份给席位 | 在线, 主召回路 |
| 字面腿 | 纯 SQL `LIKE`, 零向量零网络, 实测 5 到 7 毫秒 | 在线 |
| 本地向量竞速 | 本地嵌入与云端并跑, 谁先到用谁 | 在线 |
| 跨源腿 | 去信、来信、承诺、关切、画像事实, 按时序、关键词、状态取 | 在线 |
| 去年今日 | 纯日期匹配, 零模型调用 | 在线 |
| 记忆标题索引 | 全史标题每轮全量注入, 条数不切 | 在线 |
| `search_memory` 工具 | 主动检索, 支持按 id 取原文 | 在线 |
| 体索引 + 透镜 | 第 2、3 节 | 在线 |
| keyed 命中簇 | 话题键等值命中才发, 零命中零字节 | 在线 |
| 志 | 第 6 节: 规则常驻 + 目录 + 所在面整面拉全 | 在线 |
| keyed 历史格 | 摘要的键与本轮抽出的键相等时, 展开原文行; 摘要文本永不注入 | 关 |
| 摘要可检索 | 闲聊摘要行进入检索 | 关 (8 月起摘要只当目录) |
| 慢检索深挖 | 后台异步深挖 | 关, 观察中 |
| 亮度排序 | 第 4 节 | 关 |
| 体: 用户近况格 | — | 关 |
| 旧「点名近况」格 | — | 退, 被透镜取代 |
| 旧关系透镜 | 「我怎么看 / 什么相连」三段 | 退, 9 月底判被取代 |

(私有仓 `memory_pool/recall_store_registry.json`、`prompt_v2_config.json` 与各词表的覆盖层生效值。)

两处细节, 讲的是同一件事 —— 丢记忆比慢贵。字面腿弃用了全文索引 FTS5, 因为它的三字切分吃不下两个字的中文词 (私有仓 `jarvis_hippo_literal.py`)。语义腿预取超过 6 秒就降级走字面腿, 块头自报降级, 而不是空着发出去。

标题索引能每轮全量注入, 是因为它是标题级: 全史摘要试过一次, 约 94.1 万 token, 直接撑爆窗口; 换成每条约 40 字、模型读全文写的标题, 才放得下全部 (私有仓块登记表 g46 注)。

这张表按我们的数法, 在线 10 条、关 5 条、退 2 组 —— 数法有主观成分, 不同的拆法会得到不同的数。要紧的是形状: 检索不止一条路, 向量、字面、日期、标题、体与透镜并联; 每一条的开关都写在覆盖层上, 查得到。

## 6. 二级语料: 立场这类东西怎么治、怎么进 prompt

二级语料是指不是原话、而是从原话里长出来的东西: 立场、关切、规则、兴趣、待问的问题。它比原话危险, 因为它是加工过的, 越加工越容易偏。立场账是我们在这上面摔得最重的一跤, 下面拿它当样板。

### 6.1 病

立场原本由一个提炼腿从思考脑的念头里抽出来, 再由一个判官自动批准。2026-09 中旬实测: 转正的 23 条里有 22 条是判官批的, 批准时间中位 4.2 分钟, 证据只有一条; 同一个来源被反复提成好几张卡; 「用户有回应」这个自动标签被当成了强化。开闸时常驻的立场块有 30 万字符 (私有仓 `STANCE-SLIM-1` 转窗话术)。

### 6.2 治, 分三步

1. **二级条目必带元信息。** 来源身份、根事件、适用情境、有效性、出处版本; 机器推测不许引用机器推测去冒充用户确认; 更正走「取代」, 不改旧行。
2. **毕业要独立证据。** 要么跨两个以上来源日的独立证据, 要么用户本人一句话; 同一来源不再重复立卡。当时存量 104 条: 退 37、并 32、留 35。
3. **并进「志」。** 2026-10-17 起, 立场、关切、规则、提问、兴趣合进一本只追加的账, 叫志。旧的立场账 241 行全部还在, 状态是已退, 一行没删。

到 10-25, 志账有 418 个事件: 新增 239、批注 149、修订 27、放下 3; 折叠后在持的 236 条 = 关切 153 + 规则 35 + 立场 34 + 提问 7 + 兴趣 7。239 条新增全部带出处引用, 标「无出处」的是 0 条 (私有仓 `memory_pool/hold_ledger.jsonl`)。

### 6.3 写口与撤回

- **谁写。** 用它的那颗脑自己写, 没有第三方审批; 判官链已经退役。缺出处不拒收, 落账时标「无出处」, 不伪造一个。
- **引原话会被回查。** 出处里引了用户的原话, 系统去原账里对; 对不上标「引文未核」, 照样保留, 让读的人看得见。
- **撤回不删行。** 放下写一条放下事件, 带理由; 修订写一条修订事件, 旧版留在账上。

### 6.4 怎么进 prompt

规则全量常驻在 u1 段; 目录 (每张面一行计数) 和醒因所在的那张面放在 u2。取的时候按面、按醒因整面拉全, 不按全局排序取前 N 条; 走证据面的 `cap` / `units`, 不加帽 (私有仓 `jarvis_hold_render.py` 头注)。旧的立场常驻块、立场 keyed 块、关切全文块等 15 项, 由志接住后关闭。

### 6.5 还没做到的

出处引用只证明「有一根指针」, 不证明指针指向的内容撑得起这条结论; 这一步我们还没有语义核验。更正传播目前只写一张票, 下游的派生条目不会自动跟着改。

## 7. 我们也压过

开头说的「压缩有损」, 我们不是旁观者。

贾维斯早期有一条「梦境压缩」产线: 把 7 天前的闲聊压成摘要 (私有仓 `jarvis_hippocampus.py` 的 `compress_chat_history`)。旧行为是压完之后软删源行。有一阵子, 闲聊原文删了 2,267 条、只剩 38 条活着, 摘要成了唯一的痕迹, 两个人共同经历过的事对检索不可见。

更糟的是摘要追不回原文。2026-09-16 的一次普查: 107 条摘要里, 只有 13 条带着能精确对回原文的 id 链 (私有仓 `docs/TODO_ARCHIVE.md`)。剩下的 94 条, 没有一条能精确指回它压缩的是哪几行原话。一次跨章重述里, 主脑说自己没见过用户的脸, 其实三天前刚见过照片 —— 事实在重述中丢了, 而重述不带源 id, 所以连「是哪一步丢的」都查不到。

于是改了三件事:

1. **摘要只当目录, 原文才是内容。** keyed 注入的是原文行加指针, 摘要文本不注入 (私有仓 `jarvis_hippo_digest.py` 头注)。眼下这个注入口的闸是关的, 我们照实写。
2. **源行不再删。** 覆盖层上压缩后软删源行这一项设成了 0; 入库的默认值仍是 1, 作为一条看得见的红线留着, 代码注释写了缘由。今天库里闲聊原文活着 5,400 条, 软删 12 条。
3. **标题账喂全文。** 进 prompt 的字面截断, 核到最后只剩 3 处。治法是给每条记录写一个标题: 模型读全文写, 代码里有静态检查锁住不许切片; 标题只当目录, 全文留在原账 (私有仓 `jarvis_body_title.py`)。标题账现在 29,123 行。

摘要产线没有删, 最新一条摘要写于 2026-10-23。它现在的身份是目录, 不再是记忆本身。我们的判断是: 压缩本身不是错, 错在让压缩产物顶替了原文的位置。

### 靠纪律, 无机器闸

下面几条我们一直在守, 但没有专名的锁测或棘轮, 所以不说「保证」:

- **记错比忘了更糟。** 拿不准新说法是不是覆盖旧说法, 就新旧并存、标冲突、送裁, 不静默覆盖。
- **时间章是事实发生的时间, 不是落库的时间。** 回填时传事实时间, 落账行另记回填时刻。
- **持续为真的事进状态账, 不当事件处理, 不吃过期时间。**
- **少给可以, 少给不说不行。** 预览必须标明全文在哪。
- **治数据, 不治检索。** 30 个长期记忆错例逐个归因: 53% 病在账本身, 30% 在写进去的管道, 检索侧只占 13%。
- **不另起一个模型当审核闸。** 病在源头修; 判断归两颗脑。

## 9. 一个例子: 一位朋友的弟弟

一位朋友提过她有个弟弟。助手对话里记下了这件事, 可一条旧的抽取把它挂到了另一个人名下 —— 代词归属错了 (那条抽取腿 10-18 已退役)。而且这件事只在「近况 7 天窗」里出现过一次, 窗口一过, prompt 里只剩一行标题。

你再问起她弟弟, 主脑面前没有这条。

修完以后我们做了一次零花费的离线回放 (10-22): 同一位朋友的 30 个对话轮, 两条关于弟弟的记录, 在旧的「点名近况」格里 60 次全不在; 换成透镜之后, 59 次以一行档出现, 1 次在尾段, 60 次全部找回。

这是离线回放, 不是线上统计; 量具没有入仓。但它说明了一件事: 材料一直都在, 缺的是从这个人到这条记录的边, 和一个放得下它的分辨率。
